## 1. Architecture
```
collectors (launchd 1800s) ──▶ ct_ tables (marrow.db)
                                    │
wake daemon (launchd KeepAlive, always on) ──reconcile (60s cadence)──▶ decision ──▶ wake.run_wake
     Scheduler-hosted (synapse_core); 2 deadlines:       ct_pacemaker_state       │
     <shell>.reconcile (fixed) / <shell> (business)      ct_wake_log        note → iTerm window (resident claude); failure → alert, round given up
```

## 3. Wake daemon + reconcile (`daemon.py`, `reconcile.py`)
> Pacemaker package (core/triggers/gates/integration/pacemaker_tick/sentinel) deleted whole, T11 P4. The trigger decision engine (event/affect_flag/self_scheduled triggers, gate collision) is retired — the durable next_wake_at ledger is the only wake source. What survives: one fixed interval, `[wake].default_sleep_min` 20 (occupancy.schedule_next_wake, §7). Same number as `[wake.watchdog].silent_max_min` and marrow/synapse tg `shell_idle_min` — cross-repo contract, keep all three equal.
- daemon.py WakeDaemon embeds synapse_core.Scheduler over an AF_UNIX kick socket (config.daemon_socket_path, <=104 bytes). Two deadlines per scheduler shell key (Scheduler holds ONE per key; firing consumes it): `<shell>.reconcile` (fixed [daemon].reconcile_interval_sec cadence, self-rearms) and `<shell>` (business = the armed next_wake_at if any, else the silence-round due — never min()'d; safety_horizon_sec when idle; retry_interval_sec after a held/failed fire) (daemon.py:96-160).
- Idle window = MINIMUM interval: an armed next_wake_at suppresses the silence cycle (daemon.silence_due_in, watchdog.silence_action); a due alarm is cleared BEFORE run_wake so an interrupted delivery is still consumed (daemon._fire_wake); a window already overdue at daemon start re-arms from now instead of firing (daemon._reset_overdue_silence → wake_state.stamp_silence_basis). A pending kick_round is an explicit request and passes all three.
- Every callback re-arms on entry AND in a `finally` (daemon.py:170-184) so a consumed Scheduler entry or a raised exception never leaves a key unarmed; `kick()` no-ops on a key with no entry, so the business key must always stay armed.
- Blocking work (reconcile_once/business_once) runs via `asyncio.to_thread` so the kick socket stays responsive; an `asyncio.Lock` serialises the two callback bodies against each other (daemon.py:112,173,181).
- reconcile.py `_reconcile`/`_handle_awake`: ledger reconcile relocated verbatim from the retired pacemaker_tick entry point (T11 P4) — circuit-breaker hold (`breaker.holds(cfg, config.shell_id(cfg))`, §4.1), manual adopt (`[wake].auto_adopt`, under the spawn lock), dead+due fire (rotated?fresh:resume via `_fire_dead_window`), accidental-close resume, SILENT resume of a window closed while ASLEEP (`wake.resume_asleep`: reopen `--resume` under the spawn lock, re-record session_id via an epoch-guarded conditional_mutate, NO bell / NO set_awake / ledger untouched — the window sits idle until the scheduled wake fires), watchdog heal (respawn if pidfile dead), silence backup (delegates to watchdog.silence_action), stale-suspect debounce (`confirm_ticks` consecutive dead verdicts, epoch-guarded against a lie_down/reset mid-pass) (reconcile.py:21-100,227-264).
- Fire path: synthesize a decision dict (`reasons`/`wake_reasons` kick|next_wake_at|silence|reconcile, ctl.py precedent) → `wake.run_wake`. Ungated — no `[gates]` section; sole brake is `[pacemaker].dry_run`, on BOTH fire paths (daemon business + reconcile dead-window): log-only, next wake still re-armed.
- daemon._fire_wake: the alarm is consumed before delivery, so EVERY non-window outcome — mode≠window, dry_run, or a raised exception (logged, never propagated) — re-arms the next wake. A crashed round cannot lose the alarm.
- kick.py `_notify_daemon` → `synapse_core.send_kick(socket_path, shell)`: state writes (reason queue / gen bump / ledger clear) land first, then the kick makes the daemon re-read instantly instead of waiting for the next reconcile cadence. Unreachable socket → wake_audit row + stderr, wake deferred to reconcile.
- Breaker scope = `[daemon].shell` (config.shell_id) on every autonomous path — daemon, reconcile, watchdog, fuse tally. Manual kick pierces the breaker by design (single message only; autonomous paths stay held).
- launchd `KeepAlive = {SuccessfulExit: false}`: exit 0 (disabled / shell off / lock held) must NOT relaunch; only a crash does.
- No more one-shot exact-time process (sentinel.py, deleted): the business deadline itself fires at the exact computed time via the Scheduler; lie_down's `persist_next_wake_at` (lie_down.py:196-207) writes the ledger then kicks the socket instead of spawning/killing a `sleep N` subprocess.
- `[daemon]` config: enabled, shell, socket_path, kick_timeout_sec, reconcile_interval_sec, safety_horizon_sec, retry_interval_sec, lock_path (config.py:224-241). Singleton lock = `daemon.lock` (daemon.py:229-253).

### 3.1 Circuit breaker (`breaker.py`) — the main switch
- ONE persistent file stops cortex AUTONOMOUS activity (auto wake / spawn / fed round / watchdog reap) for the shells it covers. Bridges keep running, tg/wx chat is unaffected, manual commands still work. Survives every restart; only an explicit clear releases it. It replaced the old per-shell `wake_state.paused` DND flag entirely (one truth, cross-shell, durable).
- **State file** `<marrow config dir>/breaker.json` (= parent of marrow.db, `config.marrow_config_dir`):
  `{"scope": "all"|"cli"|"tg", "reason": "auto_fuse"|"manual", "ts": "<local iso>"}`.
  File ABSENT = breaker clear. Corrupt / wrong-shape / empty scope = read as CLEAR + one warning log (a broken breaker must never freeze the shell). flock on a `.lock` sibling around read-modify-write, tmp+`os.replace` write.
- **Fuse tally** `<marrow config dir>/fuse_events.json`: `{"events": [{"ts": "<iso>", "shell": "cli"|"tg"}, ...]}`. BOTH shells append to this one file; entries older than `window_hours` are pruned on every write, so `len(events)` after a write IS the rolling cross-shell count. Bare ISO strings are tolerated and normalised.
- **The JSON file IS the cross-repo protocol.** synapse ships its own independent copy of this logic (`synapse_core/breaker.py`) — schema shared, code never imported across repos (same rule as shell_state).
- **Config: marrow only.** `[cortex.breaker]` in `~/.config/marrow/config.toml` (defaults in marrow/config.default.toml): `enabled` / `fuse_threshold` / `window_hours` / `trip_message`. `breaker.settings()` reads that toml directly and layers it over `breaker.DEFAULTS`; missing file/section/key → defaults. Deliberately NOT duplicated into cortex.toml or the tg bridge config. There is no clear/resume message: only the auto trip announces itself.
- **Manual pause MERGES, auto trip overwrites.** `trip(..., merge=True)` (via `breaker.pause` = every `ctl pause`) unions the new scope with the standing one under the flock: cli+tg → all, all+one → all, same shell → ts refresh. Plain `trip` (auto fuse, scope "all") stays last-writer-wins.
- **Choke points (cli)** — all four sit BEFORE the alarm is consumed, so `next_wake_at` survives a hold and fires on the first pass after a clear: `daemon.reconcile_once`, `daemon.business_once` (before `_fire_wake` clears the ledger), `reconcile._reconcile`, `watchdog.run`'s poll loop. There is deliberately NO check inside `wake._spawn_serialized`: every autonomous spawn path already passes one of the four above, and a check at the lock would land AFTER `_fire_wake` consumed the alarm (strictly worse). The manual paths (`ctl wake`, `wake.py --force`) CLEAR the breaker first — no silent bypass.
- **Auto trip (cli)**: `watchdog._fuse` calls `_record_fuse` at fire time (before the grace phase, so a hung fuse still counts) → `breaker.record_fuse_and_maybe_trip(dir, "cli")`. Count >= `fuse_threshold` and `enabled` → write scope="all", reason="auto_fuse". `enabled = false` still tallies, never trips. On trip `watchdog._announce_trip` writes a `critical` / `cortex_breaker_tripped` row into marrow `alerts` AND a pending `outbox` row target='tg' (the tg bridge delivers it) — both raw writes into marrow.db, same shape as `wake._alert_respawn_failed`; both best-effort, a failed announcement never stops the breaker standing.
- **ctl** (`ctl.py`): `pause [--shell cli|tg]` → breaker on, merged (default scope all), silent — no outbox row, no alert row (a manual pause is not an incident); a live cli window is put down through the EXISTING proxy `lie_down(force_slept="ct-pause", book_alarm=False)` — the same path the watchdog fuse uses, no new interrupt mechanism. `wake [--shell cli|tg|all]` → release that scope, then kick it NOW (below). `resume [--shell]` → clear without kicking; a cli release with an empty, asleep ledger books a due-now `next_wake_at` (`_book_cli_alarm`) because `pause` books none and `daemon.business_reason` returns None for asleep + empty + no kick reasons = sleeps forever. `status` → breaker + duty + ledger state. `pause`/`wake`/`resume` are plumbing only — the exposed command surface is `/ct-duty` (§3.2).
- **ctl wake per shell**: `cli` → `breaker.release(cfg,"cli")` + the standard `run_wake` pipeline (already-awake-on-duty stays a no-op). `tg` → `breaker.release(cfg,"tg")`, `shell_ledger.write(<shell_state_dir>/tg.json, next_wake_at=now)`, then a one-line `"tg\n"` kick to `config.shell_socket_path` (marrow `[cortex].shell_socket`, default `<shell_state_dir>/tg.sock`) — the same `synapse_core.scheduler` wire format `cortex.kick` uses on the cli daemon socket. The ledger write is the durable half; the kick is best effort (dead bridge → the booking fires on its next pass) and the output line says which happened. `all` → clear the whole file + both kicks, tg first. `shell_ledger.py` is cortex's copy of the `<shell>.json` protocol (flock + tmp/replace merge; synapse's copy is `synapse_core/shell_state.py`, never imported across repos).
- Cortex exposes NO MCP tool to set or clear the breaker: human + auto-trip only.

### 3.2 Duty rotation (`duty.py`) — who runs
- State file `<marrow config dir>/duty.json`, path derived as a sibling of `breaker.json` (`duty_path` = `breaker.breaker_path(...).with_name("duty.json")`, no separate config key — relocating breaker moves both): `{"mode": "cli"|"tg"|"off"|"all", "hold": "cli"|"tg"|"all"|null, "ts": iso}`. `mode` = intent, `hold` = the materialised pause scope — enforcement reads `hold` only. Each field is validated on its own (cross-repo agreement: the tg bridge reads `hold` alone) — an unknown mode never invalidates a valid hold, an unknown hold value reads as no hold, absent/unparseable → mode "all", hold null (fail-open, breaker convention). flock on a `.lock` sibling, tmp+`os.replace` write. No `enabled` flag — mode "off" is the only stop-everything state.
- Mode → hold (`hold_for`): `off`→all, `cli`→tg, `tg`→cli, `all`→null.
- `breaker.covers` unions the manual/fuse scope with `duty.covers(config_dir, shell)` (breaker.py:143-150); duty never writes breaker.json — the sole exception is `ctl duty <mode>`, which clears it inside the transition (§3.1: after the new hold is written, before any kick).
- `apply(cfg, mode, after_hold=None)`: writes the new hold to disk FIRST, then puts down whatever shell is newly covered, then kicks every shell the hold leaves free — no instant exists where both shells are active. The WHOLE transition runs under the duty flock (write + put-down + kicks), so two racing transitions cannot interleave into both shells active; nothing it calls re-takes that lock (the read path never locks). `after_hold` runs once the hold is on disk and before any action — `ctl duty` clears the breaker there. Naming a shell always kicks it now (not only on release): repeating a mode re-kicks the named shell (the cli already-awake guard and the idempotent tg booking make a repeat harmless); mode "all" kicks both (tg first), "off" kicks neither.
- Put-down (`_put_down_cli`) fires only when the cli window is live-awake, via the same proxy `lie_down(force_slept="duty", book_alarm=False)` path `ctl pause` uses — silent, never fatal to the hold.
- Fresh-vs-resume gate (`[duty].fresh_token_threshold` 80000 / `fresh_age_hours` 8, `_cli_needs_fresh`/`_tg_needs_fresh`): the incoming shell spawns fresh instead of resuming once its window is over the token threshold OR its last activity is older than the age bound. cli source = `transcript.window_tokens`/`transcript.mtime` (never re-parsed), both now read the RESIDENT transcript (§9) — bare `newest()` measured whichever headless `claude -p` jsonl shared the projects dir, so a transfer from tg judged tg's own in-flight file instead of the cli window; over the gate → `wake_state.set_retired_sid` (only when a pointer exists — a None would WIPE an earlier rotate's retirement) + `set_rotated` before `ctl._wake_cli` — the old session is retired (never resumed), its window left OPEN for the user to close. tg source = the shell ledger's `occupancy` + `last_user_ts`/`last_note_ts`; over the gate → `ctl._wake_tg(cfg, rotate=True)` books `rotate_pending` so the bridge respawns instead of resuming.
- `transfer(cfg, shell)` (duty.py:306-324) — the on-duty shell's own handover: refuses when a manual/fuse breaker stands (`ERR_BREAKER_HELD`; only `ctl duty` clears it, transfer never does). Otherwise `apply(cfg, other_shell(shell))` — duty moves to the caller's target, so the hold that results covers the CALLER's own shell: it goes quiet where it stands, judged by the fresh-vs-resume gate only at its own next takeover. No lie_down, no rotate issued here.
- Wake-source tag (`wake_source.py`): `apply(source=, from_shell=)` stages a one-shot line for each shell it is about to kick — cli in `wake_state.wake_source`, tg in its ledger — and that shell's own wakeup note renders it as the first header line. Templates `[duty].transfer_source_text` / `ctl_source_text` / `hold_none_label`; placeholders `{from_shell}` (transfer origin), `{shell}` (now on duty), `{hold}`. `duty.transfer` passes KIND_TRANSFER, `ctl duty` KIND_CTL, an auto wake passes nothing and its note is unchanged. Pending-visible: `note.gather` peeks, only `note_render --mirror` (the delivering render — marrow's injection hook and the tg host) takes it.
- `main()` / `--transfer SHELL` — the CLI entry marrow's `transfer` MCP tool shells out to: `python -m cortex.duty --transfer <shell>` (marrow/MAP.md §6.2).
## 4. Wake runner (`wake.py`)
- run_wake: symlinks.ensure_all → assemble_note → window path (the only path). Freshness from rotate flag, no date compare; next-morning first wake = rebirth.
- WakeTimer latency probe always-on: wake_id + timing_path passed as constructor args (no env vars); marks tick_fire→gate_eval→symlinks→note→injected/failed/complete (timing.py).
- _window_wake_plan classifier: fresh (rotate flag | `transcript.window_transcript` ≠ recorded) | resume (sid dead/gone, no flag) | ear (alive+unrotated; None recorded hint stays ear). Consumes rotate flag once/wake. Window-lineage resolution, not `newest()`: a foreign headless jsonl being mtime-newest used to read as a mismatch and respawn a healthy window. Trade-off: a `/clear` (new session, no wake marker) now classifies as ear, not fresh.
- _window_wake path: fresh → _spawn_wake(resume=False) emoji; dead+no-flag → _resume_or_fresh_dead (sid → --resume same convo; absent → fresh, plain).
- Alive → type bell (type_wake_signal) → _signal_landed polls mtime 3s up to ear_timeout 90s.
- _ear_miss_ladder (alive): type_wake_signal rearm → poll → land=ear; claude dead → _resume_or_fresh_dead; rearmed-unconfirmed → set_awake anyway.
- Two alert points, both via `_alert` → marrow `alerts` row (audit_log fallback): respawn failure (WindowError, `cortex_respawn_failed`) and the window path giving up a round (`cortex_wake_window_failed`).
- Two visible wake lines, two config keys: `[wake].spawn_opener_template` = the first prompt baked into a FRESH spawn (fresh_initial_prompt, also transcript.lineage_marker for finding resumable sessions); `[wake].wake_bell_template` = the line TYPED into a live resident (type_wake_signal, resume bell). Each path writes its OWN template into the wake_state receipt (write_wake_receipt(opener=…)); machine data (gen/state_id/rearm) stays in the receipt sidecar; the marrow hook matches the on-screen line against the receipt (shape fallback tries BOTH templates) → injects the full note. Both prefixes feed transcript._line_markers so neither counts as user speech.
- _spawn_wake P0 timing: record NEW transcript only after _wait_new_transcript (~8s poll for jsonl newer than pre-spawn or mtime≥spawn_ts); timeout → record None never stale (stale drove endless respawn loop).
- None hint + alive + no flag → ear.
- No headless path: window path None → _audit_wake + _alert → `{"mode": "failed"}`, round given up, cursor/alarm state untouched. Every caller (daemon._fire_wake / ctl.cmd_wake / reconcile._fire_dead_window) re-arms next_wake_at on any non-window result, so an alarm consumed at fire time is never lost.
- Note gathered EXACTLY once per wake: assembled after the plan is classified (inside the spawn lock), so a rotate no longer double-gathers and eats its own kick reasons.
- _audit_wake best-effort inserts audit_log, swallows all. CLI: --force (bypass gates) | --print-note.

### wake_state.json (`wake_state.py`)

### watchdog (`watchdog.py`)
- Per-wake detached subprocess spawned at set_awake; pidfile self-guarded (unlinks only own pid, watchdog.py:29-40,169-181). Not started when marrow's `[cortex].shells` omits "cli" (watchdog.py:588-589, config.shell_enabled).
- Poll 60s: retires when awake cleared externally; publishes occupancy via store_window_tokens each poll.
- Fuse: window_tokens>=[wake.watchdog].fuse_tokens (300k live; marrow's 150k soft nudge fires first) → _fuse then exit; else silence_action (watchdog.py:458-511).
- Silence loop (silence_action, watchdog.py:394-485, shared by watchdog.run + _handle_awake + daemon business): every silent_max_min (20) of user silence → inject one free-round block → re-arm the SAME timer from that instant → repeat forever. The session stays up until it calls lie_down itself.
- Silence basis (wake_state.silence_basis_min): newest of the transcript read and the hook-stamped `last_user_msg_ts`, else awake_since when the user never spoke this wake. The transcript lags the marrow hook, which drops tuck_pending in the same write — transcript-only re-fires a round on top of the user's own message.
- tuck_pending (last-fire marker) is stamped under the epoch lock BEFORE delivery, so an esc-interrupted or failed injection is still consumed (no retry, no re-fire inside the window).
- That stamp also CLAIMS the round (bumps gen), so watchdog poll and daemon business tick racing the same round deliver exactly one line — symmetric with claim_lie_down.
- Free-round round = the SHORT tuck_in_text `[NEW ROUND]` line is the ONLY thing typed; the freshly rendered note is staged to `wake_state.free_round_note_path` (`[paths].free_round_note_file`, default <home>/free_round_note.md) and injected INVISIBLY by the marrow hook on that marker turn (read+consume, TTL = receipt_ttl_min) — same bell→note chain (`[wake].free_round_note` toggle, watchdog.py:_build_tuck_in_line/_deliver_free_round). Staging APPENDS (the ct-note round types a second marker right after) and a failed type un-stages, so no orphan payload. The note carries no Replay — the marker turn runs hooks, so turn_inject is that window's replay outlet.
- ct notes (F9) ride the same invisible chain: claimed AFTER the first round commits, staged, second short marker typed (_deliver_ct_notes).
- tuck_in_text MUST carry the `[NEW ROUND]` marker: an unmarked line counts as user speech and resets the cycle it just armed (perpetual-loop trap).
- No-user wake → silent_min timed from awake_since (no user-message ts to derive it from), same bar.
- Kick carrier (kick.py mark_kick_round) short-circuits the silent_min gate: inject now, then re-arm the same cycle.
- Commit is epoch-guarded (conditional_mutate): a lie_down/user reset between build and write drops the injection (BUG B).
- watchdog._log = timestamped heartbeat to watchdog.log (start/retire/fuse/silence_action) — proves the dedicated watchdog is live vs riding only the tick backup (watchdog.py:336-345).
- force_slept="auto" = routine silence marker, distinct from "timeout" (retired) and real incidents (fuse/stale). Ledger/audit only — the note never renders it (§6 pause tag).
- _fuse: record the fuse on the shared breaker tally FIRST (`_record_fuse`, §3.1) → esc → write `⚙️ [FUSE]` marker (body = marrow [cortex].fuse_prompt_text: update own handoff + lie_down(rotate=True)) → poll awake 300s grace; proxy-lie_down only if session didn't; force_slept set only when handoff unwritten (watchdog.py:166-205).
- esc verify: still growing → hard_interrupt SIGINT, gated hard_interrupt_enabled (43-66).
## 5. lie_down / say
- Env-gated MCP tools in marrow daemon (MARROW_CORTEX=<shell>) via `-m cortex.<mod>`; also CLI mains for watchdog proxy use. lie_down = every shell; say = cli only (marrow/MAP.md §6.2).
- lie_down (lie_down.py): next_wake_min REQUIRED at MCP/CLI, normalised by lie_down.clamp_next_wake_minutes into TWO bands at EVERY hour — 0-`[wake].next_wake_low_max` (55) ∪ `[wake].next_wake_high_min`-`[wake].next_wake_max` (180-360); 0 = immediate re-wake. Inter-band gap unselectable (prompt-cache TTL — a sleep there buys a cold start, no rest): snaps silently to the nearer edge, out-of-range clamps to the ceiling/0, never an error. `human_override=True` (explicit ctl minutes) pierces the bands. Proxy callers (fuse/stale) may pass None for `[wake].default_sleep_min`.
